# Data Contract

This file documents the JSON fields passed between pipeline stages. The field names should stay stable unless all downstream consumers and validation checks are updated together.

## TriviaQA Input Fields

### `QuestionId`

Original TriviaQA question identifier.

Rules:
- Must exist for selected examples.
- Must not be blank after normalization.
- Matching against generated records uses normalized IDs.

### `Question`

Original question text.

Rules:
- Must be a non-empty string for answer sampling.
- Whitespace may be stripped before writing generated records.

### `Answer`

TriviaQA answer metadata.

Important nested field:
- `NormalizedAliases`

These aliases are used to compute `gold_correct` during verification.

## Generated Question Fields

### `question_id`

Normalized generated question identifier.

Rules:
- Must match a TriviaQA `QuestionId` after normalization.
- Must not be blank.
- Duplicate normalized IDs are rejected in matching stages.

### `original`

Original question text stored in generated output records.

Rules:
- Must be a non-empty string in baseline and `cp_fixed` records.
- Llama and Qwen records must agree on stripped `original` text when combined.

## Cross-Prompting Fields

### `paraphrases`

Final valid paraphrases kept after semantic-equivalence checks.

Comment:
If no valid paraphrases survive, cross-prompting falls back to the original question.

### `paraphrases_generated_llama`

Paraphrases generated by Llama.

### `paraphrases_generated_qwen`

Paraphrases generated by Qwen.

### `answers_responsed_llama`

Answers sampled from Llama.

The spelling is kept for compatibility with existing outputs.

### `answers_responsed_qwen`

Answers sampled from Qwen.

The spelling is kept for compatibility with existing outputs.

### `answers`

Generic answer list used by baseline records.

Rules:
- Must be a list.
- Each answer must be a string.

## Semantic Entropy Fields

### `semantic_ids`

Cluster IDs assigned to answer samples.

### `semantic_entropy`

Entropy value computed from semantic answer clusters.

### `final_answer`

Representative answer selected from the majority semantic cluster.

### `selected_model`

For cross-model outputs, identifies whether the final selected answer came from Llama or Qwen.

## Verification Fields

### `gold_correct`

Boolean indicating whether the candidate answer matches TriviaQA normalized aliases.

Rules:
- Must be a boolean before final hallucination labeling.

### `rag_verification`

RAG verifier label.

Expected values:
- `SUPPORTED`
- `NOT_SUPPORTED`
- `ABSTAIN`
- `PARSE_ERROR`

Rules:
- Required as a non-empty string when `gold_correct` is false.
- Normalized before final label assignment.

### `retrieved_chunks`

Evidence chunks returned by the retriever.

### `is_hallucinating_true`

Final hallucination label.

Rules:
- `False` if `gold_correct` is true.
- `False` if RAG verification is normalized to `ABSTAIN`.
- Otherwise depends on the verification result and final labeling logic.

## Compatibility Notes

- Do not rename JSON keys casually.
- Preserve awkward historical spellings such as `answers_responsed_llama` and `answers_responsed_qwen`.
- Validate malformed rows before mutating or saving outputs.
- Keep pure data helpers in `src/hallucination_detection/data_utils.py`, not `src/hallucination_detection/generation.py`.
